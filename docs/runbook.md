# Runbook

## Проверка состояния

После запуска открой `GET /actuator/health`. Ответ `UP` означает, что приложение и обязательные
проверки готовы.

В каркасе анонимно доступны только health и probes. Остальные HTTP-пути, включая метрики, отвечают
403. Правила JWT-доступа будут добавлены вместе с контрактами OAuth API.

## Сервис не запускается

1. Проверь `docker compose ps`.
2. Проверь `DATABASE_URL`, `DATABASE_USER` и `DATABASE_PASSWORD`.
3. Если включено шифрование, проверь наличие `CONNECTION_TOKEN_KEYS_CURRENT_VERSION` и всех ключей,
   на которые ссылаются строки в базе. Значения ключей не выводи в терминал и issue.
4. Запусти `./gradlew test`.
5. Не записывай token, authorization code и client secret в issue или лог.

## Ротация ключа

1. Добавь новый случайный 32-byte ключ в secret manager с новой версией.
2. Оставь предыдущие версии доступными для чтения.
3. Переключи `CURRENT_VERSION`: новые token начнут шифроваться новым ключом.
4. Старый ключ нельзя удалять, пока связанные записи не перешифрованы или не удалены.

Если версия из `key_version` отсутствует, сервис специально откажется расшифровывать token. Не
подменяй версию и не очищай credential вручную без процедуры отключения подключения.

## Восстановление данных

Backup должен включать таблицу `account_connections`, но сам по себе недостаточен: версии ключей из
secret manager резервируются отдельной защищённой процедурой. Потеря старого ключа делает связанные
refresh token невосстановимыми; их придётся подключать заново.

Истёкшие и погашенные строки `oauth_sessions` не содержат raw state или открытый verifier. Фоновая
очистка будет добавлена вместе с OAuth flow; до этого их можно удалять только по `expires_at` после
резервного копирования и без вывода encrypted columns в логи.

При `redirect_uri_mismatch` сравни `GOOGLE_OAUTH_REDIRECT_URI` с Google Cloud Console посимвольно:
scheme, host, port, path и trailing slash должны совпадать. При provider 4xx/5xx не выводи response
body или request form: они могут содержать authorization code либо token.
